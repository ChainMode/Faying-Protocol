# 人類視野（Human View）

第二章已經把命題挑明：Fay 介入數位行動後，行為發起者與責任承擔者出現了結構性裂縫。Faying Protocol 提供契約的形式，但契約能否真正承接責任，取決於一項更前置的承諾：

> **任何 Fay 的行為，都必須在它所歸屬的人類原型（Human Prime）能夠「看見」的範圍內發生。**

「看見」二字在這裡不是物理意義上的視覺，是一種泛化概念：人類原型、歸屬的個人或歸屬的組織，能隨時確認其 Fay 處於監護下運作。

這種泛化意義上的「看見」，稱為 **Human View**——人類視野。它不是 Faying Protocol 中的某條欄位、某個開關、某個 API，是 Faying Protocol 全部技術決策都必須服從的價值觀。任何欄位、訊息、狀態機的設計，如果讓 Fay 脫出 Human View，那麼這個設計在藍圖層面就是不被允許的，無論它在工程上多麼便利。

## Human View 不是物理視野

物理視野是「我此刻看得見這個無人機」、「攝影機此刻拍到了機器人」。物理視野受光線、距離、遮擋、注意力的限制。它在很多場景下根本不可能成立——一個人類原型不可能 24 小時盯著自己所有的 Fay。

Human View 描述的是一種結構性可確認：

- 不要求人類原型此刻正在看它的 Fay；
- 但要求人類原型任何時候想看，都能立即確認這個 Fay 是否處於監護之下；
- 也要求 Fay 的行為留下可追溯的痕跡，使得「剛才發生了什麼、歸屬於誰」可以被回溯地確認。

換言之，Human View 關心的不是「被看到」，是「**可被看到**」。這是它能夠在無數高自動化場景——無人機叢集、家庭機器人、企業流程 Fay——中仍然成立的關鍵。

## 四反命題：四種被禁止的情境

定義一項價值觀最有力的方式，是說明它禁止什麼。Human View 顯式禁止以下四種情境，稱為 Human View 的**四反命題**。

**未經授權（Unauthorized）**——Fay 在沒有取得人類原型授權的前提下展開行動。「取得授權」是一項可被驗證的行為，不是 Fay 自己聲稱的狀態。一個 Fay 即使深信「人類原型一定會同意我這樣做」，也不構成已被授權。

**未授意（Unintended）**——Fay 擁有某種合法授權，但本次具體行動並未被人類原型顯式表達過意圖，且與人類原型當下的意圖發生偏離。授權解決「能不能動」，授意解決「動這一下」。Human View 要求兩者同時成立。

**不知情（Unaware）**——Fay 既被授權也接受過授意，但人類原型在事實上無法在合理代價內得知 Fay 正在做什麼。這種情境往往不是 Fay 主動隱瞞，而是協定設計的缺陷——它讓資訊無法回流到人類原型一側。Human View 把「資訊的可達」視作監護關係的硬條件。

**脫離控制（Out-of-Control）**——人類原型已經知情，但已經無法即時干預，比如 Fay 拒絕接受撤銷指令、拒絕中止任務、拒絕降速。這一情境是其餘三種的最終化形態：當 Fay 既不必徵得授權、又不必透露行動、又不必接受干預時，「監護」就只剩下一個名字。Human View 要求干預通路始終敞開。

四反命題不是相互排斥的清單，是逐層加深的失守邊界：未經授權是入口失守，未授意是過程失守，不知情是回饋失守，脫離控制是最後一道閘門失守。Faying Protocol 必須在四個層次上同時守住，才算履行了 Human View 這項價值觀。

## 同時適用於 iFay 與 coFay

Human View 不是只針對個人型 Fay（iFay）的約束，**同時適用於 iFay 與 coFay**。

iFay 與某個具體的人類原型有顯式的對應關係，監護關係直觀。coFay 通常對應一個組織、一個團隊，或一個角色，監護關係並不天然清晰。然而，正因為 coFay 的歸屬端往往是組織而非具體個人，Human View 的要求反而需要被更顯式地表達：組織必須在制度層面明確「誰有權代表組織行使監護」，否則 coFay 就在事實上滑入了「沒有具體責任人能夠監護」的灰色地帶。

任一 Fay，無論是 iFay 還是 coFay，都不能以「我屬於一個組織、所以無人具體監護」為由游離於 Human View 之外。組織有義務把監護職責落到具體的人或具體的角色上。這不是技術問題，是價值觀問題。

## 與 Faying Protocol 的關係

Human View 是藍圖層面的價值觀，Faying Protocol 是承接這項價值觀的技術約束規範。

Human View 回答「為什麼需要某種約束」。Faying Protocol 回答「這種約束如何被技術忠實地履行」。

如果把 Human View 比作一份憲章，Faying Protocol 就是把憲章落到具體執行機構、具體程序、具體憑證上的一整套基礎法律。一份憲章如果沒有任何法律承接，它將淪為口號；一套法律如果背離了它所承接的憲章，它將變成它本來反對的東西。兩者必須互相校準：當 Faying Protocol 的某項設計讓 Fay 容易脫出 Human View，它就必須被否決，無論它在工程上多麼方便；當某種新場景讓 Human View 在現有 Faying Protocol 下難以履行，那意味著 Faying Protocol 必須被升級，而不是 Human View 被讓步。

第十二章（Faying 雙重語義）與第十三章（Rogue Fay 與責任歸屬）將從協定形態層面承接這項價值觀：第十二章說明監護關係如何被建立與維持，第十三章說明監護一旦不成立 Fay 必須如何停下。兩章合起來，是 Human View 在協定層面的具體落地。
