## §11 Open Questions

> 本章誠實陳列 Phase 1 協定正文未必須回答、留給協定委員會在 RFC 階段決議的議題。每條議題給出**當前協定傾向**、**備選方案**與**決議狀態**，以便後續 RFC 討論有結構化的起點。已決議條目（如 Q10 協定命名）保留作為歷史記錄。

### Q1 Rogue 期間終端的位置回報

- **議題**：iFay 處於 Rogue Fay 狀態期間，是否允許終端繼續回報物理位置？涉及「隱私 vs 可尋回」的兩面拉扯。
- **當前協定傾向**：按 `RevokeReason` 差異化——`human-initiated` / `task-completed` 不回報；`fay-credential-invalid` / `regulatory-order` / `terminal-disconnected` 等可回報。
- **備選方案**：（a）一刀切禁止；（b）一刀切允許；（c）由 HP 在 BOOTSTRAP 時顯式預先選擇。
- **決議狀態**：未決；藍圖第 14 章已顯式不下結論。

### Q2 G0 Emergency Override 的不可拒絕路徑

- **議題**：在 IF 已被攻擊者控制的極端情形下，G0 封包如何確保仍能被 IF 核心執行？
- **當前協定傾向**：協定層強制 G0 封包具有最高優先級（詳見 §7.2 / P12 G0 Override 優先級），但承認在 IF 核心已被攻陷時純協定層手段不充分。
- **備選方案**：（a）硬體級 kill-switch 強制；（b）TPM-quote 雙簽確認；（c）維持協定層強制並將硬體路徑留作生態實作自由發揮。
- **決議狀態**：未決；與 Phase 2 / Phase 3 終端接管深度耦合。

### Q3 PQC 預設時間表

- **議題**：Ed25519 + ML-DSA-65 hybrid 何時從 OPTIONAL 提升為 MUST？
- **當前協定傾向**：1.0 僅宣告 OPTIONAL（PQC 套件可協商位見 §6.1）；待 NIST 最終標準全部公布後再制定時間表。
- **備選方案**：（a）等待 NIST 全部 PQC 標準定稿；（b）跟隨首個標準化簽章演算法；（c）按 grade 差異化（高敏感場景率先 MUST）。
- **決議狀態**：未決；待 NIST PQC 標準化進度。

### Q4 跨人類原型的 iFay ↔ iFay 協作（Phase 4/5）

- **議題**：分屬不同 HP 的兩個 iFay 協作時，責任傳遞方式如何確定？
- **當前協定傾向**：1.0 不涵蓋；Phase 4 引入 coFay 時再定。
- **備選方案**：（a）發起方負責；（b）接收方負責；（c）按規則分擔；（d）必須雙方 HP 共同見證。
- **決議狀態**：未決；需法律—協定雙軌討論。

### Q5 Ego 偏離的客觀判定

- **議題**：協定層是否應規定 `ego-deviation` 的最低判定訊號集？
- **當前協定傾向**：協定層只定義 `RevokeReason="ego-deviation"` 的語意與觸發後果（§EH.1、§3.6 BBS）；具體判定訊號集留給實作自由發揮。
- **備選方案**：（a）協定層規定最低訊號集；（b）由 §3.6 Behavior Baseline Service 顯式約束；（c）維持當前留白。
- **決議狀態**：未決；與 Q13 行為基線標準化耦合。

### Q6 Mandate 續期策略

- **議題**：協定是否禁止「自動續期」的全部形態？
- **當前協定傾向**：禁止全部自動續期形態；每次續期必須經 HP 顯式見證（藍圖第 10 章傾向）。
- **備選方案**：（a）允許「需 HP 週期性預簽名的有限自動續期」；（b）允許低風險 grade（G3/G4）的自動續期；（c）維持禁止。
- **決議狀態**：未決；待協定委員會取捨。

### Q7 離線 / 弱網環境

- **議題**：在 RR 不可達的邊緣場景（無人機斷聯），是否允許「限時自治 + 回連後強制對帳」的弱化模式？
- **當前協定傾向**：透過 Endorsed_Mandate（§7.5、§9.8、§4.3 Disconnected）顯式建模「限時自治 + 重連對帳」；非 Endorsed 路徑嚴格 Default-Deny（詳見 P17.2 悲觀推定）。
- **備選方案**：（a）僅靠 Endorsed_Mandate；（b）引入「區域級 RR 快取」；（c）嚴格 Default-Deny 不開任何例外。
- **決議狀態**：部分決議（Endorsed_Mandate 已落地於 §7.5）；離線策略上限待 Q11 決議。

### Q8 子代理「補充等級」

- **議題**：G0 Emergency_Override 與 G1 Strict / G2 Moderate / G3 Loose / G4 Autonomous 的五級體系是否足夠？
- **當前協定傾向**：1.0 維持五級（§7.1）；不引入 G2.5 等中間檔。
- **備選方案**：（a）引入「半自主 + 可干預」中間檔；（b）允許實作自訂子等級但映射回五檔之一；（c）引入正交的 Endorsement Grades 子等級（已落地於 §7.5）。
- **決議狀態**：部分決議（Endorsement Grades 已正交疊加於 G1–G4）；中間檔維持 Open。

### Q9 撤銷級聯的邊界

- **議題**：DELEGATE 的級聯撤銷預設值（`cascade=true`）在多層派生時的可視性如何保證？
- **當前協定傾向**：預設 `cascade=true`（§5.3.5）；可見性由 `RevocationVisibilityBudget` 約束（§9.7、P14 跨派生級聯撤銷）。
- **備選方案**：（a）按派生樹深度差異化預算；（b）維持單一預算 + 推 / 拉雙軌。
- **決議狀態**：未決；待 conformance 測試摸高深層派生樹的實測可見性。

### Q10 協定命名（已決議）

- **議題**：協定正式命名。
- **決議結論**：協定正式命名為 **Faying Protocol**（無獨立縮寫），版本號 `Faying Protocol/1.0`。
- **決議狀態**：已決議；本議題留作歷史記錄，不再開放討論。

### Q11 Endorsement 最大壽命上限

- **議題**：協定層是否規定 `endorsement.endorsed_lifetime` 的硬上限（如 ≤12h）？是否再按 grade 進一步收緊？
- **當前協定傾向**：附錄 B 給出建議值（預設 4h，軟上限 12h，且不得超過 `Mandate.not_after − Mandate.not_before`，詳見 P16.3 / P16.4）；硬上限留待 RFC 決議。
- **備選方案**：（a）協定層硬編碼 12h 上限；（b）按 grade 差異化（如 G1 ≤ 1h，G4 ≤ 24h）；（c）維持建議值不強制。
- **決議狀態**：未決；與 Q7 離線策略耦合。

### Q12 雙向 Faying 濫用防護

- **議題**：iFay 主動發起的 `FAYING_REQUEST` 是否需要在協定層強制速率限制（每 (HP, IF) 對每分鐘最多 N 次）？速率限制是否納入 `ConfirmationRateLimit` 同一預算？
- **當前協定傾向**：FAYING_REQUEST 頻次納入 `ConfirmationRateLimit` 同一預算（詳見 §5.3.6、§9.10.7、P18.6）；超限按 §9.10.7 自動降級 / 暫停。
- **備選方案**：（a）獨立預算 `FayingRequestRateLimit`；（b）按 grade 差異化預算；（c）維持當前與 ConfirmationRateLimit 共享。
- **決議狀態**：部分決議（預設共享預算已落地於 §9.10.7）；閾值上限與是否獨立預算待 RFC 決議。

### Q13 Behavior_Baseline 標準化

- **議題**：行為基線的計算口徑粒度（按 `action` / `scope_used` / `risk_level` / `affected_resources`，或多維聯合）是否在協定層統一規定？還是允許實作自由發揮但要求基線計算口徑本身寫入 Attestation Chain？
- **當前協定傾向**：實作自由發揮 + 基線計算口徑本身寫入 Attestation Chain，口徑變更視為稽核事件（§3.6 I-BBS-3 / P18.5）。
- **備選方案**：（a）協定層強制（按 action / scope_used / risk_level / affected_resources 多維聯合）；（b）維持自由發揮 + 稽核；（c）引入「基線 schema 註冊中心」統一口徑。
- **決議狀態**：未決；與 Q5 ego-deviation 判定耦合。

### Q14 Atomic_Action 最小粒度的客觀判定標準

- **議題**：何為「最小不可拆分的 action」在協定層的客觀判定？是否引入「action lattice」使 `scope.actions` 與 RP 端動作集合存在可形式化對齊的最小粒度規約？
- **當前協定傾向**：協定層僅強制「一次呼叫恰好 1 個 Atomic_Action / `scope.actions` 不允許萬用字元」（P18.2 Atomic_Action_Strict）；最小粒度的客觀判定留給 RP 與協定委員會按行業領域規約。
- **備選方案**：（a）引入跨 RP 通用 action lattice；（b）按 RP 行業（金融 / 醫療 / IoT）分別 lattice；（c）維持當前留白。
- **決議狀態**：未決；與 §9.10.8 T7 可擴充槽配套討論。
