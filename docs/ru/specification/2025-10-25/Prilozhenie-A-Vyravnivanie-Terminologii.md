## Приложение A Краткий справочник выравнивания терминологии

> Это приложение согласовано с Glossary базы требований и Приложением A базы проектирования; имена систем, появляющиеся в подпунктах EARS, должны быть определены здесь до использования. Приложение организовано в пять категорий — «Роли и сущности / Компоненты протокола / Объекты данных протокола / Уровни и политики / Бюджеты по умолчанию» — для удобства перекрёстных ссылок.

### A.1 Роли и сущности

| Термин протокола (английский) | Термин концепции (ru) | Отношение / примечание |
| --- | --- | --- |
| Human Prime (HP) | Human Prime (человеческий прототип) | Синонимичны; единственная конечная точка несения ответственности и держатель полномочия отзыва Faying-отношения; также единственная сущность, которая может дать явное подтверждение изменений состояния Faying |
| iFay Instance (IF) | iFay Instance (экземпляр iFay) | Синонимичны; уполномоченная агентская сущность, однозначно идентифицируемая FayID; не обладает полномочием отозвать собственный Mandate; все изменения состояния обусловлены явным подтверждением HP |
| Supervisory Agent (SA) | Supervisory Agent (надзорный агент) | Класс регулятора, отличный от Prime и распознаваемый на уровне протокола; не обладает полномочием отзыва; не может заменить HP в завершении подтверждения Faying |
| Relying Party (RP) | Relying Party (вызываемая сторона) | Терминал, приложение или сервис, вызываемый iFay |
| Presence Device (PD) | Presence Device (устройство присутствия) | Аппаратура, несущая учётные данные WebAuthn / FIDO2 и биометрические возможности; физический источник сигналов присутствия |

### A.2 Компоненты протокола

| Термин протокола (английский) | Сокр. | Описание |
| --- | --- | --- |
| Mandate Service | MS | Логический сервис, который выпускает / продлевает / понижает / отзывает Mandate от имени HP (см. §3.1) |
| Presence Channel | PC | Низколатентный, защищённый от replay поток присутствия от PD к MS (см. §3.2) |
| Attestation Chain | AC | Обратно прослеживаемая цепочка подписей, образованная всеми действиями выпуска HP → MS → IF → производная IF (см. §3.3) |
| Revocation Registry | RR | Сервис статуса отзыва в реальном времени (см. §3.4) |
| Liveness Channel | LC | Поток выявления обрыва связи (включая фактический обрыв и воспринимаемый обрыв) (см. §3.5, §9.9) |
| Behavior Baseline Service | BBS | Статистический сервис, поддерживающий поведенческую базовую линию (HP, IF) (см. §3.6) |

### A.3 Объекты данных протокола

| Термин протокола (английский) | Термин концепции (ru) | Описание |
| --- | --- | --- |
| Mandate | Mandate (полномочие) | Новое понятие на уровне протокола; несёт поля `(issuer, subject, scope, grade, presence_req, not_before, not_after, attestation, signature, endorsement?)` (см. §4.1 / §4.2) |
| Endorsed_Mandate | Endorsed Mandate (эндорсированная авторизация) | Подтип Mandate; явно объявляет `endorsement = (enabled, endorsed_scope ⊆ scope, endorsed_grade.autonomy ≤ grade.autonomy, endorsed_lifetime, offline_revocation_policy)`, позволяя IF автономно действовать в ограниченных рамках во время физического обрыва связи; конечная точка несения ответственности — всегда HP (см. §7.5, P16.x) |
| PresenceSignal | Presence Signal (сигнал присутствия) | Утверждение физического присутствия, производимое PD и проверяемое MS |
| Attestation | Attestation (свидетельство) | Унифицированный носитель проверяемого утверждения (WebAuthn / TPM-quote / Platform-keystore / Self-signed) |
| FayID | FayID | Унифицированная уникальная идентичность iFay в рамках фреймворка iFay (ULID-подобная) |
| Faying_State | Faying State (управляемое состояние) | Поведенческое состояние, в котором находится IF, когда Mandate в Active / Degraded / Disconnected |
| Rogue_Fay | Rogue Fay (состояние отделения) | Поведенческое состояние, в котором находится IF, когда Mandate в Unpaired / Revoked или отсутствует; взаимоисключающая бинарность с Faying_State (P15). **Примечание**: `Suspended` *не* классифицируется как Rogue_Fay — это «Faying State приостановлено» (отношение мониторинга сохраняется, метаданные Mandate удерживаются, и HP может явно его возобновить без свежего BOOTSTRAP); оно лишь разделяет запрет измерения D с Rogue как поведенческое следствие; см. таблицу сопоставления §4.3 / §8.2 |
| Faying_Initiation | Bidirectional Faying Initiation (двунаправленное инициирование Faying) | Инициирование Faying-отношения (установление или корректировка) может инициироваться либо HP (HP-initiated), либо IF, запрашивающей Faying у HP (IF-initiated / FAYING_REQUEST); окончательное условие вступления в силу — HP даёт проверяемое явное подтверждение (см. §5.3.6, P16.6) |
| Behavior_Baseline | Behaviour Baseline (поведенческая базовая линия) | Накопительный поведенческий профиль (HP, IF), поддерживаемый BBS, используемый для выявления внезапного отклонения (см. §3.6, P18.5) |
| Atomic_Action | Atomic Action (атомарное действие) | Наименьшая неделимая единица объявления, которую IF выполняет наружу; один вызов соответствует ровно 1 Atomic_Action; связывание запрещено (см. P18.2) |
| Disclosure_Report | Disclosure Report (сообщение раскрытия) | Структурированное сообщение, которое IF использует при отчёте или запросе подтверждения; `mandatory_fields` обязательно разбираемы (см. §5.3.7, P18.3) |
| Ego | Ego (граница самости) | Синонимичны; используется для решения `ego-deviation` (см. §3.6, §9.10.4) |
| Human View | Human View (человеческое видение) | Ценностный фреймворк; Faying Protocol — его протокольное воплощение (глава 11 концепции) |

### A.4 Уровни и политики

| Термин протокола (английский) | Описание |
| --- | --- |
| Authorization_Grade (Grade) | Уровень авторизации, значение `G0..G4` (см. §7) |
| G0 Emergency_Override | Уровень аварийного перехвата; односторонний принудительный возврат HP (см. §7.1, P12) |
| G1 Strict | Строжайший ярус; уровень по умолчанию для высокочувствительных действий |
| G2 Moderate | Средний ярус |
| G3 Loose | Снисходительный ярус |
| G4 Autonomous | Наиболее автономный ярус; потеря heartbeat G4 напрямую → Suspended (см. §7.3) |
| PresenceRequirement | Требование присутствия; тройка `(signal_types, max_staleness_ms, on_loss)`, привязанная к уровню |
| Scope | Объём авторизации; множество минимальных привилегий с явным объявлением `(domains, actions, terminals?, budget?)` |

### A.5 Бюджеты по умолчанию (детальные значения в Приложении B)

| Термин протокола (английский) | Кратко |
| --- | --- |
| MaxMandateLifetime | Максимальный срок жизни одного Mandate (по умолчанию 24 ч, верхняя граница 30 д) |
| BootstrapTimeout | Тайм-аут ожидания свидетельства HP в BOOTSTRAP / FAYING_REQUEST (по умолчанию 60 с) |
| RevocationVisibilityBudget | Бюджет, в пределах которого отзыв становится видимым в сети RR (по умолчанию 1 с) |
| StaleBudget | Порог отклонения при недостижимости RR (по умолчанию 5 с) |
| HumanReachabilityBudget | Порог, при котором недостижимость HP запускает авто Revoke (по умолчанию 30 мин) |
| LivenessDetectionBudget | Верхняя граница окна выявления обрыва связи; монотонно ужесточается по уровню (см. Приложение B, P17.3) |
| AttentionDriftThreshold | Порог, при котором неактивность представления HP запускает «потерю внимания»; ужесточается по уровню (см. Приложение B, P18.4) |
| ConfirmationRateLimit | Верхняя граница запросов подтверждения, проталкиваемых HP за единицу времени; превышение лимита запускает автопонижение / приостановку (см. Приложение B, P18.6) |
| MaxDegradedDuration | Максимальная длительность состояния Degraded (по умолчанию 5 мин/уровень) |
