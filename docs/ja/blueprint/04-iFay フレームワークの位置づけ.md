# iFay フレームワークの位置づけ

本章は二つの問いだけに答えます。iFay フレームワークは大まかにどんな姿か？ Faying Protocol はその中でどの位置にあるか？

iFay フレームワーク自体はカバー範囲が広く、構成要素も多く、各所を少し展開すればフィールド、プロトコル、メッセージ形式といった具体的技術詳細に踏み込みます。本リポジトリの三類資産——ブループリント、プロトコル仕様、schema——は Faying Protocol のみを担います。iFay プロトコルファミリー中の Faying Protocol 以外の全メンバーは、一律に [ifay.ai](https://ifay.ai) へのリンクで参照し、本リポジトリでは再述、書き直し、派生のいずれも行いません。

## iFay フレームワークの輪郭

[ifay.ai](https://ifay.ai) の全体設計に従えば、iFay フレームワークは大まかに四層構造として理解できます。

**実体層**にはプロトコルの制約を受ける二類の知的実体が含まれます。**iFay**（Individual Fay）は具体的な Human Prime に強制的に対等にマウントされ、この帰属を離れた瞬間それは iFay ではなくなります。**coFay** は共有型 Fay であり、法的責任能力を持つ個人または組織に明確に帰属している場合に限り稼働が許されます。iFay でも coFay でも、本ブループリントが論じる Faying Protocol は同等に制約します。帰属が一度失効すれば、Fay は停止しなければなりません。

**コアコンポーネント**には各 Fay 実体内部の不可分なパーツが含まれます。**FayID** は Fay の統一一意身元識別子であり、いかなる監護関係に入る際の身元基盤です。**Ego** は特定の個人またはロール profile と整合させたベースラインパラダイムであり、Fay の価値傾向、興味嗜好、習慣、認知・スキル境界、権限境界、業務スタイルなどの次元での自律行為空間を制約します。Ego は大型 AGI モデルではなく、「人格化された境界」です。**Runtime** は Fay の仮想 Runtime であり、iFay と coFay が異なる端末、OS、組み込みアプリシナリオで互換稼働できるようにします。FayID と Ego は Faying Protocol が機能するための二つの前提条件です。前者は身元帰属を、後者は行為境界を担います。

**プロトコルファミリー**には iFay が世界と接続、感知、協働するための一連のプロトコルが含まれます。本ブループリントの主題 **Faying Protocol** のほか、少なくとも以下が含まれます。端末制御に関する双方向伝送プロトコル、人類ユーザーインターフェース向けの UI フレンドリープロトコル、iFay と coFay 間の UI 翻訳層を排した意味通信プロトコル、クラウド能力のブロードキャスト・サブスクリプションプロトコル、および将来追加される可能性のあるその他メンバー。これらプロトコルファミリーメンバーの技術詳細は [ifay.ai](https://ifay.ai) を参照してください。本リポジトリには収録しません。

**価値構造**は新しい労働構造と価値配分モデルに対応します。この層には人類労働の退出、知識のフラット化、普遍的生存保障、新しい価値創造、新しい社会階層化などの系統的変化が含まれ、MeriToken などのメカニズムが価値計測の担い手となります。これは iFay フレームワークの遠景背景板であり、Faying Protocol の仕様には直接落ちません。詳細は [ifay.ai](https://ifay.ai) を参照してください。

## Faying Protocol のその中での位置づけ

上記の四層を一緒に並べたとき、iFay フレームワークにおける Faying Protocol の位置づけはこのように精確にアンカーできます。

> **Faying Protocol は「実体層」と「コアコンポーネント」の上にあり、プロトコルファミリーの中で「受制御、監護、委託制御」の意味論を専ら担うサブプロトコルである。「FayID がある Human Prime に帰属するか」という根本的問いを、確立、維持、撤回が可能な一連の接続状態と動作に変換する。**

それは Fay の能力定義ではないため、Fay が何をできるかは規定しません。それは Fay の行為指針ではないため、Fay がどのように行うべきかは規定しません。それはただ一つの問いに答えます。

> **この瞬間のこの Fay の行動は、誰の責任か？**

このため、iFay フレームワークにおいて Faying Protocol は「最も眩い」プロトコルでも「最も深厚な」プロトコルでもありませんが、最も省略してはならないものです。それが欠けた瞬間、iFay フレームワーク全体は普通の Agent エコシステムへ退化し、第 1 章で描いた責任の空白を社会に持ち込むことになります。

## 本リポジトリと iFay フレームワークの境界

```
                 +-------------------+
                 |   ifay.ai 全景    |
                 |  iFay フレーム 4 層 |
                 +-------------------+
                          │
                          │  本リポジトリはその一員を展開する
                          ▼
            +---------------------------+
            |   Faying Protocol プロジェクト   |
            |   （即ち本リポジトリの全資産）    |
            +---------------------------+
                          │
            ┌─────────────┼──────────────┐
            ▼             ▼              ▼
        ブループリント   プロトコル仕様      schema
   docs/{lang}/    docs/{lang}/         schema/
    blueprint/    specification/       …（本期は提供しない）
   （即ち本 spec）（後続独立 spec）
```

本リポジトリの三類資産はすべて Faying Protocol のみを担います。iFay フレームワークの他メンバーの深い展開は本リポジトリの範囲ではなく、直接 [ifay.ai](https://ifay.ai) を参照してください。
